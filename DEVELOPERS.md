Developers
==========

Setup
-----

1. Install dependencies:
   - cram, for the test suite: `pip install cram`
   - pystache, to build `man/rcm.7` from its mustache template:
     `pip install pystache`
   - hyperfine, only if you want to run `maint/benchmark`:
     `pacman -S hyperfine` or `brew install hyperfine`
2. Prepare the build system: `./autogen.sh`. (This depends on GNU autoconf
   and GNU automake.)
3. Configure the package: `./configure`.
4. Make sure the tests pass: `make check`.

Testing
-------

The test suite uses [cram][]. It is an integration suite, meaning the
programs are exercised from the outside and assertions are made only on
their output or effects.

The test suite requires Perl with the `Cwd` module. It expects to find Perl as
`perl` in `$PATH`.

All tests can be run like so:

    make check

Individual tests can be run like so:

    env TESTS=test/lsrc-dotfiles-dirs.t make -e check

If you intend to write a new test:

1. Add your test at `test/subcommand-something-meaningful.t`.
2. Add the relative name to the `TESTS` variable in `Makefile.am`.
3. Source `test/helper.sh` as the first line of your test.
4. When in doubt, use existing tests as a guide.

`maint/difftest` compares this tree's `lsrc` output against unmodified upstream
rcm, over your real dotfiles. `make check` cannot catch a divergence there,
since both trees satisfy the same cram expectations.

[cram]: https://bitheap.org/cram/

Making a release
----------------

1. Bump the version within the `AC_INIT` macro call in `configure.ac`, and add
   a stanza for it at the top of `NEWS.md.in`.

2. Regenerate the build system and build the distribution tarball:

        ./autogen.sh
        ./configure
        make distcheck

   `make distcheck` unpacks the tarball into a clean tree, configures it,
   builds it, runs the test suite against it, and checks that `make uninstall`
   leaves nothing behind. It produces `rcm-fast-X.Y.Z.tar.gz`.

3. Tag the release and push the tag:

        ./maint/release build tag rcm-fast-*.tar.gz
        ./maint/release push tag rcm-fast-*.tar.gz

   The tag is signed, so this needs `gpg.format` and `user.signingkey` set.

4. Attach the tarball to a GitHub release. This is done in two steps, so that
   the release can be read over before anyone sees it:

        ./maint/release build github rcm-fast-*.tar.gz
        ./maint/release push github rcm-fast-*.tar.gz

   `build` creates a draft, taking its notes from the topmost stanza of
   `NEWS.md`. `push` publishes it.

   Attaching the tarball is not optional. GitHub's automatically generated
   source archives are the contents of the git tree, which does not include
   `configure` or `man/rcm.7`; they cannot be built without autoconf,
   automake and pystache.

5. Generate the Arch package and install it:

        ./maint/release build arch rcm-fast-*.tar.gz
        cd arch && makepkg -si

   `build arch` writes `arch/PKGBUILD` with the release URL and checksum
   filled in. `makepkg` then downloads from that URL, so the release must
   already be published; this doubles as an end-to-end check of the artifact.

   Publishing to the AUR is not automated, and `./maint/release push arch`
   says so rather than doing anything. `arch/git-PKGBUILD`, generated by
   `configure`, builds from the tip of `main` instead of a release.

6. Update the Homebrew formula in the `fictionic/homebrew-tap` repository.
   Both `url` and `sha256` change:

        sha256sum rcm-fast-X.Y.Z.tar.gz

   Homebrew takes the version from the tarball filename, so there is nothing
   else to bump.

7. Remove the tarball:

        ./maint/release clean github rcm-fast-*.tar.gz
